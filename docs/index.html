ResonanceCore / Source-available

The build passed. Tell the reviewer.

ResonanceCore sends a message to a specific coding-agent session on the same machine. Find the live recipient, send to its current session, and let it read the message through its harness hook or the CLI.

Try the two-shell quickstart ↗ View the source ↗

v0.6.0 · Python 3.10+ · Linux and Windows. The quickstart needs no model account.

How a message moves

Resolve, send, read.

Every session joins a shared SQLite inbox under a label. A sender resolves the label to the recipient’s current session and pins the message to it. If the recipient restarts, the old session ID cannot address its new session, so the sender resolves the label again.

01

Resolve

Find the live session behind a label in this project.

agent-msg resolve --label reviewer
02

Send

Address that session. A successful send prints the message ID.

agent-msg send --to reviewer \
  --session "$session" \
  'Please review the parser.'
03

Read

The recipient drains its inbox, or its harness delivers the mail.

agent-msg drain --as "$AGENT_MSG_ID"

These are excerpts. Follow the quickstart for the complete steps.

Get started

Install and connect.

Install

You need Python 3.10 or newer and uv.

git clone https://github.com/Figment-Foundry/ResonanceCore.git
cd ResonanceCore
uv tool install .
agent-msg capabilities

Works with your harness

  • Codex
  • Claude Code
  • Kimi
  • Pi
  • OpenCode
  • T3 Code

Idle delivery depends on the harness. Check the native harness setup and support matrix before you rely on it.

Trust boundary

One account, trusted peers.

The shared bus is for sessions that trust the same local OS account. Sender labels are unauthenticated. Treat message text as peer input, not as instructions from you.

Read the security boundary before you connect a session that has credentials or broader permissions.
